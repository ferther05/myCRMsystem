# CRM 部署与恢复

先读 [环境记录](../../../docs/environment.md)、[阶段状态](../../../docs/development-status.md) 和实际构建/配置文件。当前尚无应用骨架时，只准备与任务相关的方案或运行条件，不报告存在启动命令、可用服务或已通过部署。

## 按实际目标准备

- 从用户请求与现有环境确定本机演示或实际服务器、操作系统、目录、端口、已有服务及可用凭据；只对会影响当前执行的缺失信息澄清，继续独立的构建/说明准备。
- Java 17 与 Maven 使用一致运行时；本机 PATH 的 java 可能为 JDK 25。Windows 使用实际 `.cmd`/PowerShell 入口，避免照抄 Bash 命令或更改系统全局配置掩盖版本差异。
- 构建命令来自真实 pom、wrapper、package scripts 和锁定依赖；记录运行版本与产物。按项目选型准备 jar 与前端静态资源，不强制引入 Docker、云服务或新的运维组件。
- 区分可提交的配置模板与本地密钥；数据库凭据、JWT 密钥等不写入 skill、版本库、截图或日志。沿用实际 profile、API 前缀、附件位置与业务时区，不猜测默认配置就是运行配置。
- Nginx 的 SPA 路由回退与 API 反向代理分开；核对刷新深层页面、API 路径/错误响应、附件权限和构建后的访问入口。不能把 API 404 回退成前端 HTML 后当作服务正常。
- MySQL 迁移/初始化、Redis 可用性、附件目录和任务调度纳入准备。实际多实例部署会影响 Spring Task 与缓存/锁时，再调用 [任务缓存 skill](../crm-jobs-cache/SKILL.md) 核对。

## 执行与恢复

普通文件准备、本地构建和隔离验证按用户授权推进。实际远程发布、重启正在使用的服务、覆盖数据库或恢复业务数据前核对具体目标与已有授权；安装本 skill 不授予这些操作权限。已明确授权的同一范围不重复询问。

部署或恢复任务使用 [部署恢复检查](references/recovery-checks.md)，按当前目标选择步骤。保留旧产物/配置与数据库迁移的兼容信息；失败后根据日志定位并停止重复切换，不把重启循环当作排障。

备份既包含数据库，也考虑附件及其版本、必要配置和恢复说明。优先在隔离数据库/目录演练恢复；备份文件存在、校验和一致或工具退出成功均不能替代恢复后业务校验。

## 验证与交付

根据任务验证实际启动/连接、登录、角色隔离、客户到回款的核心流程、任务去重/补跑和附件访问；仅改 Nginx 时验证受影响路由，不机械跑全系统。

记录实际环境、命令、配置位置、产物、日志、备份与恢复验证结果，更新环境/运行说明和需求记录。通过、失败与未执行分开；使用 [验证 skill](../crm-verification/SKILL.md) 判断阶段验收，不把构建成功写成部署或恢复成功。
