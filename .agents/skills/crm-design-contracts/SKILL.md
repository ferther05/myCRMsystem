# CRM 数据与接口设计契约

从项目根目录读取 `AGENTS.md`、[项目范围](../../../docs/project-scope.md)、[业务决策](../../../docs/business-decisions.md) 和当前 [需求覆盖记录](../../../docs/requirements-traceability.md)。原始依据在 `docs/reference/`；已有代码、迁移和接口文档用于核对实际实现，不把参考表清单当作已经落地的数据库。

## 按任务选择范围

- 阶段 0 或整体设计：使用 [设计覆盖检查](references/coverage-checks.md)，覆盖全部六个必选模块，形成实体关系、字段/枚举、接口与权限的一致约定。
- 结构变更：只核对受影响实体、接口、调用方、历史数据和验证场景，给出兼容或迁移影响；不每次重建全套设计文档。

## 关键设计约束

- 区分客户唯一归属、客户下多商机和商机协作授权；不能用一个 `owner_id` 表达所有关系，也不能把商机协作等同于客户全档案权限。
- 分开商机阶段、活跃度、客户聚合状态、签约状态和回款状态。状态动作包含前置条件、目标状态、后置动作与失败结果；相关规则使用 [业务状态 skill](../crm-business-state/SKILL.md)。
- 检查资料版本、回款计划版本/期次、业务事件与待办接收人等历史关系。明确稳定业务身份、唯一键、乐观锁条件和删除行为，避免只画 ER 连线却遗漏并发约束。
- 字段字典写明含义、类型、长度/精度、可空、默认值、编辑者和敏感级别。金额采用 BigDecimal/DECIMAL；时间阈值同时说明起点、边界、时区和按自然日或经过时长计算。
- 接口区分查询、字段编辑、状态动作和审批。明确方法/路径、参数白名单、响应、分页、HTTP 状态及业务错误；沿用 `{ code, message, data }` 和 `{ total, list }` 的项目约定。
- 列表、详情、写入、统计、导出和文件下载均标明角色/团队/本人/协作范围与字段规则，使用 [权限 skill](../crm-security-permissions/SKILL.md) 核对授权语义。
- BD-01～BD-12 中未决的状态、金额、账号开通与数据关系标注依赖；给出候选及影响，继续无依赖部分。不能以文档定稿为由自动确认公开注册、部分回款或客户终态。

## 交付与核对

根据当前任务更新实际设计文件，可用 Mermaid 表达 ER、状态或交互关系；图、字段字典和接口中的名称保持一致。OpenAPI、迁移框架和文档生成库根据已有项目或用户选择使用，不额外设为必装依赖。

给出需求来源、设计结论、未决依赖和受影响模块。核对关键路径在实体、接口、权限和验收条件之间能互相对应；交接给 [后端开发](../springboot-mybatis-development/SKILL.md) 与 [前端开发](../vue3-elementplus-development/SKILL.md)。只有实际执行过初始化 SQL 或契约检查才报告通过，设计完成不等于应用可运行。
