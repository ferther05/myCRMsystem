# CRM 设计覆盖检查

整体设计时检查下面的业务关系；局部变更只读取相关项。它们是需求覆盖线索，最终表名、拆分方式与字段以确认后的设计为准。

## 六模块与跨模块关系

- 用户权限：用户、角色、权限、团队与成员关系；账号创建/申请语义依赖 BD-12；个人资料可编辑字段与身份、角色、团队字段分开。
- 客户联系人：客户、联系人、标签/分层、有效跟进、公海领取和归属历史；按需要覆盖报备、预警、申诉、关怀、离职交接与只读期限。
- 商机：一个客户对应多个商机；跟进归属与时间影响依赖 BD-11；阶段历史、报价/客户确认、协作关系、停滞与接管动作有明确记录。
- 合同回款：商机与合同关联、签订进度、资料及其版本/确认记录、回款计划版本与期次、实收明细与核销关系；部分核销与最终应收口径依赖 BD-05。
- 分析看板：漏斗、排行、转化率和回款趋势注明时间口径、数量/金额、状态范围、零分母与数据权限；明确从哪些业务事实聚合，缓存不改变统计含义。
- 任务日志：业务事件身份、接收人、提醒日期、处理/解除、执行与失败补跑；每日去重不能吞掉不同接收人，关联 BD-06/07/10。
- 附件与审计：文件关联具体业务/版本，保存实际访问控制所需关系；必要操作人与业务时间来自后端，历史事件不因当前归属变化丢失。

## 字段与数据库约束

对当前实体核对主键/关联键、唯一性、金额精度、时间、逻辑删除、版本、创建/更新审计以及敏感级别。索引服务于实际列表筛选、权限范围、任务扫描与统计查询，不预先为所有字段建索引。

解释客户唯一归属、重复领取、版本提交、重复核销和待办去重由哪些数据库条件/约束保证。说明关联完整性由数据库外键或应用维护的实际方案，删除和历史保留行为保持一致。

## 接口最小契约

每个受影响入口记录：需求编号与业务动作；方法和路径；请求字段/校验；返回字段与分页；角色、对象范围和脱敏；状态前置条件；事务、幂等/并发冲突结果；稳定错误语义；对应验收场景。

状态动作不能开放任意 `status` 字段覆盖；批量操作说明逐条失败或整体事务的实际约定。归属、角色、确认人、核销结果等后端决定字段不得由通用 DTO 任意写入。

## 交付尺度

整体设计应能沿客户录入、有效跟进、公海领取/回收、商机推进、签约、分期回款和待办解除追踪完整闭环。局部设计只更新受影响契约及其调用方；保留未决 BD 与兼容影响，不把未执行的 SQL 或测试写为成功。
