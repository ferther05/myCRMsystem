# CRM 毕业设计材料与证据

读取 [项目范围](../../../docs/project-scope.md)、[需求覆盖](../../../docs/requirements-traceability.md)、[阶段状态](../../../docs/development-status.md) 和与当前材料有关的原始依据。开题材料完整提取见 [参考记录](../../../docs/reference/opening/opening-extracted.md)；学校模板或用户指定格式优先，缺少模板时采用可编辑结构并标明尚未核对学校格式，不虚构学校要求。

## 内容与实现对应

- 用 [证据记录约定](references/evidence-record.md) 对应需求、设计、实际实现、测试/截图与材料中的主张。只整理当前文档需要的内容，不在每次功能修改时生成整篇论文和全套交付件。
- 覆盖六个必选模块；任务与日志纳入验收。解释 RBAC 数据范围与脱敏、商机有限状态机、公海阶段/活跃度双维度回收、任务去重和处理后解除的设计及验证。
- 需求说明写预期行为，设计说明写采用的方案，实现章节依据实际路径/API/数据结构，测试章节依据已执行证据。对尚未实现、临时简版、未执行验证和未决 BD 分别标注，不相互替代。
- 原任务表“样例”有 23 条任务且序号 20 重复，按单元格与任务内容追踪。日期冲突使用 BD-13，账号注册使用 BD-12；参考表“正常进行中”和空白审批栏不能当作当前进度或通过结论。
- 论文中的图、表、字段、状态名和实际系统一致；测试环境、数据来源/规模、角色、操作、预期及实际结果可复现。演示数据和模拟结果明确标注，不冒充真实企业客户或真实业务成效。

## 引用与效果主张

核对所引用文献的作者、题名、年份、出处和可访问的 DOI/来源。无法核实的条目记录“未核实”，引用格式按学校或用户要求处理；不编造文献、页码、教师意见、成绩或签字。

开题材料中“超 60% 企业缺乏专业 CRM”等表述属于来源中的断言，未核实来源前不作为已证实统计。转化率提升、性能提升、成本降低等效果仅使用真实、可比的实验或业务数据；没有测量时保留为目标或设计动机。

## 文件制作与交付

需要 DOCX、XLSX、PDF 或 PPTX 时，调用当前环境可用的 documents、spreadsheets、pdf、presentations skill，遵循其运行时、渲染及验证要求；本 skill 负责内容和证据对应，不替代文件工具。插件暂不可用时保留可编辑内容并明确缺少的导出/验证步骤，不重复安装同类插件或声称完成文件验收。

答辩内容按实际题目、问题、设计机制、实现演示、验证结果和限制组织。更新实际交付清单与相关需求状态，说明本次修改、证据、未完成内容和文件位置；材料完整不等于系统功能已经验收。
