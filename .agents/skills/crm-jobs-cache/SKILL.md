# CRM 任务与缓存

读取 [业务决策](../../../docs/business-decisions.md) 中 BD-06/BD-07/BD-10，以及相关详细设计 2.7/2.8/9/10。

## 任务规则

- Spring Task 是应用内部业务任务，与 Codex automation 无关。按实际单实例部署设计，不为未来假设强制引入分布式调度。
- 时间与业务规则使用可注入 Clock；定义业务时区、扫描窗口、重跑身份和事件日期。调度时刻不能决定业务条件本身。
- 客户回收依赖最新活跃度与审批/回款，按 BD-10 确认顺序或事务内重算；回收前再次验证，条件更新保护扫描后的变化。
- 查询、判定、分批执行、日志分清边界，单条失败不回滚整批。写“执行中”日志不是锁也不是完整幂等机制；断点恢复与失败状态需实际可用。
- 待办按稳定事件身份去重，支持专员＋经理等多接收人及完成闭环，见 BD-07。两次运行同一天不能重复生成，跨天提醒依据业务频率。
- 多实例确需协调时明确数据库约束/锁或带所有权 token 的 Redis 锁；不能依赖无条件 DEL 或只有过期时间的锁保证所有场景。

## 缓存规则

- 字典参数变更后的热更新、权限矩阵变更与归属转移都明确缓存失效范围；数据库事务提交后再失效。
- 看板键包含统计类型、身份/团队/授权范围、时间和筛选；默认管理员缓存不得被其他用户命中。
- Redis 不可用时按真实业务降级：可回源的统计回数据库，不能为吞错跳过权限/额度验证。额度计数的原子性由后端一致性规则处理。
- TTL、空值缓存、防热点等只针对真实访问模式选择，不把全部 Redis 模式都引入项目。

## 验证与输出

验证同日重跑、跨日、跨月/年、部分失败补跑、扫描后业务变更、多接收人和角色缓存隔离。普通功能不通过修改系统时间或等待数天来测试。

报告任务依赖、幂等身份、缓存键/失效行为、实际执行结果及限制，并更新对应需求。
