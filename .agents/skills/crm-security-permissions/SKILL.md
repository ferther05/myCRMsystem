# CRM 权限与数据保护

读取 [业务决策](../../../docs/business-decisions.md) 中 BD-08/BD-11，以及 [权限检查矩阵](references/access-matrix.md)。以实际用户、团队、业务关系和数据状态定义权限，而非只检查“已登录”。

## 开发与检查

- JWT 验证签名、到期和接受的算法；用户状态、权限/团队变更与会话撤销不能永远依赖旧 token 中的角色。账号密码使用 BCrypt，首次改密按原需求处理。
- 统一身份上下文，请求结束清理 ThreadLocal；异步操作传入授权所需的不可变快照。不要假设新线程继承当前身份。
- 列表、详情、修改、阶段动作、上传/下载、日志、导出、统计都应用数据范围。按 id 直接访问仍需对象级鉴权；更新用允许字段白名单。
- 商机协作人只访问参与商机的必要数据与允许动作。跨团队协作须显式窄授权，不能简单全局跳过行级隔离。
- L1～L5 字段规则在 VO/序列化/导出和日志统一处理，不以 UI 隐藏保护明文。归属改变后及时失效详情、权限与统计缓存。
- 文件下载检查当前关系与具体业务资料权限；限制类型、大小、路径与存储访问。不是所有文件都可公开 URL；日志不写密码/token/附件内容。
- 导出明确范围、字段和授权，默认脱敏，明文导出审批/水印按已确认需求执行；浏览器按钮权限不能代替后端校验。
- 文档指定 localStorage token 存储是参考选型。改变会话方案时说明行为和迁移影响，按当前授权处理，不自动全项目安全改造。

## 验证

使用三类角色、同/异团队专员、商机协作人、交接只读/过期用户直接请求接口。既验证应拒绝，也验证合法操作仍可完成；仅验证菜单不同不足以证明隔离。

本次输出给出受影响入口、关系/字段规则、允许/拒绝证据和未定事项。用户要求系统级威胁建模时再使用 `security-threat-model`，不把普通功能修改扩展成全系统审计。
