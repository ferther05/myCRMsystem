# 权限验证矩阵

## 数据关系

- 专员：本人归属客户与允许负责商机；对公海按字段规则查看、按资格领取。
- 经理：所管理团队数据与规定审批；不能把“经理”角色直接解释为全系统经理。
- 管理员：系统管理与全量范围，但仍校验动作状态、金额及并发规则。
- 商机协作人：只参与商机的必要字段与跟进，不访问客户全档案、其他商机、推进回退、签约和回款动作。
- 原负责人：交接只读期是否成立依据 BD-08，明确 expires_at 与读/写入口；停用账号不自动恢复登录。

## 字段范围

公海 L1 基础信息可见，L2 联系方式脱敏，L3 工商决策链、L4 金额合同回款、L5 过程附件不展示。私海仍须先通过对象关系授权，不能只因角色是“专员”展示全部。

手机号、座机、邮箱、微信、信用代码按统一规则转换。低权限接口不返回原值、可解码副本、内部预览链接或在错误信息暴露敏感对象。

## 验证入口

列表与分页总数、详情、更新删除、阶段动作、跟进、上传下载、资料版本、日志、统计、导出、批量操作。测试替换对象 ID、扩大筛选、修改 owner/team、访问过期下载链接、角色切换后缓存与刷新 token。

每次范围变化检查数据库过滤和缓存键；万级统计缓存至少区分授权范围以及筛选/时间维度，不能在应用内存或 Redis 复用管理员结果。
