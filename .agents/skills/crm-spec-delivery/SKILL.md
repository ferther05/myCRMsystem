# CRM 需求与交付

## 项目依据

从项目根目录读取 `AGENTS.md`、[项目范围](../../../docs/project-scope.md)、[业务决策](../../../docs/business-decisions.md) 和 [阶段状态](../../../docs/development-status.md)。只读取与当前功能相关的参考章节，全文在 `docs/reference/`。

## 工作流程

1. 把请求对应到 [需求覆盖记录](../../../docs/requirements-traceability.md) 中的需求编号，给出可观察的验收条件。参考文档中的安排不能替代用户当前指示。
2. 核对业务语义、所需数据实体、读写接口、前端页面、权限及跨模块影响。明确不适用项，不为填清单制造无关组件。
3. 若触及 BD 待定项，依据原章节提出具体候选与影响，只暂停依赖该结论的实现；其他已授权工作继续。日常命名、组件拆分等可自行决定。
4. 按现有代码推进一个可运行的功能切片，选择相关开发 skill，不把每个请求升级为完整重构。
5. 验收使用真实环境和可重复检查；输出通过、失败、未执行原因与剩余依赖。仅编写代码不能把阶段标为通过。
6. 更新需求覆盖和阶段记录，写入实际路径、接口与证据。只改动与本次结果有关的文档。

## 阶段依赖

准备 → 骨架 → 权限 → 客户 → 商机 → 签约回款 → 任务 → 看板 → 测试部署。用户可以调整顺序；保留依赖与补齐记录。

客户简版回收在商机活跃度尚未实现时可用于开发验证，但必须登记临时差异；商机阶段结束后补齐六道闸，再做最终回收验收。

## 完成说明

用简短文字说明结果、对应需求、实际验证、剩余问题。部署、远程推送、公开分享等只在用户已授权时执行；技能安装不授予这些权限。
