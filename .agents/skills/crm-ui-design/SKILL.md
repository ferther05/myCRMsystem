# CRM 页面设计与原型

读取 `AGENTS.md`、[项目范围](../../../docs/project-scope.md)、详细设计第 11 章及本次涉及的 [业务决策](../../../docs/business-decisions.md)。检查实际前端目录、现有设计约定与接口契约；已有界面和用户明确偏好优先于参考模板。

## 按任务选择产出

- 新页面：先确定目标角色、页面目的、信息优先级和可执行动作，再设计布局与交互。按需要输出页面说明、线框图或可预览原型，不为每个任务固定生成整套文档。
- 全局视觉规范：读取 [视觉契约](references/visual-contract.md)，维护统一 tokens 与 Element Plus 映射；不另建相互冲突的组件主题。
- 客户、公海、商机、签约回款、待办或看板设计：读取 [页面模式](references/page-patterns.md) 中相关部分，将动作关联到实际业务状态与权限。
- 优化已有界面：先指出影响完成任务的具体问题，沿用现有组件修复。只改本次范围；单个按钮或文案调整不触发整站重设计。

## 设计与交付约束

- 面向中小企业中文销售后台，优先保证表格、筛选、表单和批量操作的可读性。桌面布局与窄屏行为一并考虑；新拟态、玻璃背景、营销式大标题、深色模式和复杂动效按实际需求取舍。
- 实现型交付使用项目既定 Vue 3 与 Element Plus。选择实际已有的 JS/TS、图标和图表依赖；原生 HTML 只用于用户需要的预览原型，不替换应用技术栈。
- 描述加载、空数据、搜索无结果、失败、无权限、提交中、版本冲突等适用状态。状态标签同时包含文字；不能只靠红绿色或按钮隐藏表达规则。
- 后端返回的脱敏字段直接展示；不给原型或页面安排“获取明文再遮住”的流程。协作人的可见内容以商机窄授权为准，不能默认开放完整客户档案。
- 数据、金额、枚举及统计口径依据已确认契约；“成交”与“赢单”分开。涉及待定 BD 的状态与操作标记依赖，继续设计不受影响的部分。
- 预览所需的合成数据只用于本次原型并标注来源与用途；不得包含真实客户隐私，不把示例值写进正式统计或验收成果。默认不添加演示数据到业务库。
- 原型可保存到已有设计目录；尚无约定时可使用 `docs/ui/`，主题代码放入实际前端样式目录。PlantUML/Figma 等只在任务需要且工具可用时使用，不因制作原型自动安装工具或注册外部服务。

## 检查与衔接

检查中文长文本、金额对齐、表格横向溢出、键盘焦点、表单标签、错误恢复及颜色对比度。普通文字达到 WCAG AA 的 4.5:1，大文字为 3:1；对需要辨识的控件边界/状态使用适用的 3:1 要求。根据实际相邻颜色计算，不能沿用参考资料的合格标记。

动效尊重 `prefers-reduced-motion`；焦点和有效操作不依赖悬停。窄屏需保留可到达的导航与主要动作，不能仅隐藏侧栏。布局切换使用合适断点，`clamp()` 用于连续缩放而非代替所有响应式规则。

原型可预览时检查实际效果并记录限制。进入应用实现后衔接 [Vue 开发](../vue3-elementplus-development/SKILL.md)；真实页面验证使用 [playwright](../playwright/SKILL.md) 与 [验收](../crm-verification/SKILL.md)。设计文件存在不代表接口联调或角色权限已通过。
