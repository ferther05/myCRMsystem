# CRM 代码审查检查清单

功能完成、缺陷修复、提交前审查或用户要求评审时按改动选读。聚焦能造成错误或妨碍维护的事实，不因使用本清单自动扩展为全系统审计。

## 编码与契约

- 沿用实际格式化与命名配置，检查误用依赖/API、重复逻辑和职责混杂。行长、方法行数、圈复杂度可帮助定位问题，但不以模板阈值强制拆分或新增设计模式。
- Controller/Service/Mapper、Entity/DTO/VO 职责清楚；接收字段有白名单，身份、归属、确认人及版本结果不由客户端任意赋值。
- 接口 HTTP 状态、错误码、分页、日期/金额和前端处理一致；异常不会被吞为成功。关键业务理由有必要说明，不要求所有简单访问器都写重复 Javadoc。

## 安全与数据范围

- Spring Security/JWT 与对象级权限覆盖本次受影响入口，包括列表、详情、修改、业务动作、下载、导出及统计。合法角色仍能完成操作。
- MyBatis 对输入值使用参数绑定；动态排序/表名等无法直接作为值绑定的片段使用允许列表。使用 ORM 或 `#{}` 不能代替对整个查询路径的检查。
- 客户/团队归属、商机协作窄授权、L1～L5 脱敏与缓存范围遵从 [权限 skill](../../crm-security-permissions/SKILL.md)。权限变化后旧 token、缓存与只读交接按实际方案处理。
- SQL、日志、异常、附件 URL 与导出不泄露秘密或敏感明文。Vue 的 `v-html`、动态 URL 和富文本使用按实际来源检查编码/净化；普通文本插值不无故升级为全面安全改造。
- 依赖问题核对实际版本与可验证漏洞信息，说明受影响路径。参考资料的 OWASP 编号混用了分类，不作为标准符合性证据。

## 性能与资源

- 定位循环内查库、N+1、无界列表/导出、缺失分页、潜在慢查询和不必要重复统计。按实际查询与数据规模评估，不能仅看到嵌套循环就断言性能差。
- 数据库/Redis 缓存隔离、提交后失效、失败恢复与真实统计口径一致；缓存命中不能掩盖越权或过期资金数据。
- 检查连接/流/线程池释放、前端监听器取消、ECharts dispose/resize 和重复提交恢复。性能结论需实测支持。

## 架构、状态与事务

- 模块化单体边界与依赖方向保持清楚；本次重构不自动升级为微服务、工作流引擎或财务系统。
- 公海领取、用户额度、商机推进、合同确认、回款幂等和资料版本由正确的数据库条件/约束保护；前端按钮禁用或先查后改不足以证明并发正确。
- 核对事务边界、审计与缓存后置动作，以及失败补偿。状态或资金行为有 BD 依赖时说明限制，不能偷偷选择口径后宣称通过。
- 定时任务去重、依赖顺序、补跑与闭环按实际方案处理；记录字段编辑不被误当有效跟进。

## 审查结果

问题记录可核对的文件位置、触发条件、实际影响、优先级与最小修复建议；区分已确认缺陷、需要验证的疑点及维护建议。无明确缺陷时如实说明检查范围和限制，不凑“前五问题”或任意质量分数。

已有专项审查能力按任务需要使用；用户要求系统级威胁建模时才进入对应流程。审查发现的资金、权限和并发缺陷以可重复回归验证收尾，审查清单完成不等于运行测试通过。
