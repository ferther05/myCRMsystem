# CRM 单元、集成与浏览器测试设计

根据改动选读对应类型，业务场景见 [scenarios.md](scenarios.md)。测试证据以实际运行结果为准。

## 单元测试：规则、状态与时间

- Java 使用项目实际的 JUnit 5 与 Mockito/断言依赖；前端沿用已有测试框架。Vite 项目选择新测试框架前核对兼容性，不因模板使用 Jest 自动添加整套依赖。
- 用 Arrange–Act–Assert 组织测试，根据业务条件参数化。真实 null 使用 `@NullSource` 等明确数据源，不将 CSV 中的字符串 `"null"` 当空值。
- Mock 数据库/外部服务等边界，保留真实值对象与规则计算。断言返回状态、拒绝原因及需要的副作用，不以 `verify(mapper)` 代替业务结果。
- 状态机验证允许边、非法跳转、缺少条件和回退原因；“成交”与“赢单”分开。有效跟进不完整时验证业务时钟不刷新。
- 金额用 BigDecimal 测正常、负数、零、超过余额及精度边界。数值相等与显示 scale 的要求分开验证；舍入规则取自已确认契约。
- 注入 Clock 控制阈值前、恰好达到、阈值后和业务时区跨日。自然日/满小时等有冲突的口径按 BD 决策，不改系统时间或依赖真实等待。

## 集成测试：API、权限、事务与数据库

- 从实际接口定义或代码确定方法、路径、HTTP 状态与 `{ code, message, data }` / `{ total, list }` 契约。断言身份、数据范围和响应字段，不照搬示例中的 `$.id` 或固定 201。
- 可用 Spring Boot Test + MockMvc 检查 HTTP 模拟调用；随机端口真实 HTTP 测试与 MockMvc 模式按目的选择。明确实际走过的过滤器、认证入口及事务边界。
- 普通接口校验可用测试身份；JWT 签名、过期、停用账号和权限撤销需要覆盖实际认证链，不能靠绕过过滤器的测试证明。
- 准备专员/经理/管理员、同异团队与协作账号，既测非法 ID 替换和越权拒绝，也测合法操作成功。公海响应、导出、日志和下载各自检查。
- 事务、唯一键、条件更新、MyBatis-Plus 乐观锁和并发使用真实兼容的 MySQL 测试数据库。采用独立配置和受控 fixture；可选已有容器工具，缺工具时明确未执行，不默认增加 Docker 或把 H2 结果视作 MySQL 一致性证明。
- 从独立查询或事务提交后的连接核对客户归属、用户计数、资金余额和必要审计。诱发业务失败后核对回滚；测试方法自身的回滚不能掩盖实际提交结果。
- 并发测试用开始屏障制造重叠，收集每个任务的返回值与异常。使用明确超时、finally 清理线程池/数据，不吞异常或无限等待。多个线程使用独立事务/连接，不能共享一个测试事务后声称已测并发。
- 同客户争抢至少验证唯一成功、唯一归属、计数和审计一致；同用户抢不同客户验证配额。回款验证重复请求与不同期次并发均不能导致超合同余额。
- 文件、Redis 与数据库之间的后置动作依据真实一致性方案验证，不假设测试回滚会恢复所有外部状态。

## 功能测试：角色与完整流程

- 复用项目已有 [playwright](../../playwright/SKILL.md) 及其 Windows 入口；不因参考资料使用 Playwright MCP 而自动新增 MCP 配置或下载另一套工具。
- 用例记录编号、模块、角色、前置数据、步骤和预期结果。编号可采用 `TC-CUSTOMER-001` 等形式，按业务模块维护，不照搬招聘/订单样例。
- 等实际前后端服务可运行后测试登录、客户联系人与跟进、公海领取、商机动作、资料驳回/确认、回款和待办闭环；截图用于支持关键结果，不代替断言。
- 关键异常包括输入缺失、服务端校验、401/403、版本冲突与网络失败。锁定次数/时长来自已确认配置，账号不存在提示与认证方案一致，不把模板的“5次/15分钟”变成新需求。
- 优先用 label、role 和稳定标识定位，避免 Element Plus 的内部 CSS 结构或中文列表行号。等待可观察状态，避免固定 sleep 作为主要同步方式。
- 每个角色独立会话和 fixture，退出/重新登录核对路由、缓存与敏感内容清理。浏览器验收不能替代直接 API 的对象级权限验证。
- 临时 CLI 浏览器操作与持续回归测试分开记录；只有明确需要重复运行时才落地可维护的测试套件。

## 覆盖与报告

覆盖率用于发现遗漏。用户或项目没有约定时，不机械追加 80%/90%/100% 门槛；先证明资金、归属、权限、状态与定时任务的必要路径。统计分母、排除项和工具版本明确；覆盖率高不等于业务正确。

记录环境、代码版本、数据准备、实际命令、预期/实际、通过/失败/未执行、证据路径与清理结果。依赖 BD 的预期标明待定，不把模板里的通过数、截图或模拟响应写成运行结果。
