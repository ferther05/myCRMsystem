# CRM Vue 页面开发

读取 `AGENTS.md`，定位详细设计第 11 章对应页面及实际后端契约。先检查项目现有目录、组件和 package scripts，复用已存在的设计与技术选择。

## 实现流程

- 按模块组织 API 与页面，组合式 API 管理状态；用户/权限/字典用 Pinia，避免多个页面复制身份和枚举。
- axios 统一处理 token、业务错误与登录失效，避免并发 401 重复跳转。后端字段名、分页、日期和错误码与契约一致。
- 表单有后端对应的约束；提交中禁用重复操作，保留业务失败信息。状态推进/确认仅调用合法动作接口，不提交整个实体任意改状态。
- 页面明确处理加载、空列表、错误、无权限、审批驳回、版本冲突等实际状态。浏览器重新登录不同角色时清理旧权限、路由和敏感缓存。
- 路由与按钮按权限展示，但不承担数据隔离。后端已脱敏的字段直接展示，不能请求明文后再用 CSS 或前端函数隐藏。
- 上传与下载通过受保护接口；区分资料当前版/历史版及确认状态，历史记录不覆盖。
- ECharts 使用可释放的实例和 resize 处理；核对接口统计范围及零分母，金额/日期显示保持后端约定。图表计算不能偷偷改变统计口径。
- 沿用实际项目的 JS/TS 选择，不无授权把全项改成 TypeScript 或替换 UI 库。

## 验证与交付

根据 package.json 执行实际构建、类型或既有测试。用 [playwright](../playwright/SKILL.md) 操作真实浏览器检查关键流程、窄屏、表单错误和角色差异；浏览器测试不代替后端越权测试。

只有用户要求业务演示数据或项目已有开发 fixture 时才使用相应数据，并标明来源。确认 API 不存在时登记依赖，不把 mock 页面当作已联调。

更新对应需求的页面路径、API 依赖、实际验证和剩余问题。
