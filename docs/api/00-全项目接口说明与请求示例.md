# 全项目接口说明与请求示例

2026-10-18：本文件汇总当前全项目已实现接口、请求示例、规则和页面映射。后续每个功能均同步本文件和独立模块 Markdown；未实现接口不列为已可调用。

按功能查阅：[BASE · 基础健康检查](01-基础健康检查.md)、[AUTH · 账号认证与密码](02-账号认证与密码.md)、[USER · 内部账号申请与管理](03-内部账号申请与管理.md)、[PROFILE · 个人资料](04-个人资料维护.md)、[PERM · 角色与数据范围](05-角色与数据范围.md)。接口编号在模块内保持稳定，例如 `AUTH-01 · 账号登录 · POST /api/auth/login`；页面另用 AUTH-P01 等编号。

## 公共地址、响应与分页

后端地址 `http://127.0.0.1:8080`，前端本地开发地址 `http://127.0.0.1:5173`。前端使用同源 `/api` 开发代理；未开启跨域通配符。接口只返回 JSON，认证通过 `Authorization: Bearer <accessToken>`。

成功响应为 `{ "code": 0, "message": "操作成功", "data": {} }`；无结果时 data 为 null。失败仍使用 `{ code, message, data }`，结合 HTTP 状态判断。

分页约定 `page` 从 1 开始（默认 1）、`size` 为 1～100（默认 20），data 为 `{ "total": 0, "list": [] }`。这是已落地的公共分页结构；业务分页接口随模块实现。接口返回独立 VO，不返回 Entity、密码哈希或 SQL。本人身份不返回内部版本；账号管理和申请列表返回并发提交需要的 version，不能据此伪造签名令牌。

## 公共错误语义

- HTTP 400：参数/JSON 不正确 `40000`；字段校验失败 `40001`；原密码错误 `40002`；新旧密码相同 `40003`；账号配置规则 `40004`。
- HTTP 401：缺少登录身份 `40100`；登录失败 `40101`；令牌无效/过期/已撤销 `40102`。
- HTTP 403：无操作权限 `40300`；必须先改初始密码 `40301`。
- HTTP 404：进入 MVC 后资源不存在 `40400`；HTTP 405：方法不支持 `40500`。
- HTTP 409：数据版本、唯一键或完整性冲突 `40900`；角色/团队调整前需业务交接 `40901`；HTTP 415：内容类型不支持 `41500`。
- HTTP 500：未处理错误 `50000`，不包含堆栈或 SQL；HTTP 503：依赖不可用 `50300`。

仅 GET 健康检查与 POST 登录允许匿名访问；其他未登录请求先由安全过滤器返回 401，包括尚未实现的业务路径。数据库查询失败不降级为信任旧 JWT。

下面按功能汇总完整内容，分模块文档可单独查阅。后续更新时保持两处内容一致，旧入口 [backend-api.md](../backend-api.md) 继续导航到本目录。

## BASE · 基础健康检查接口与规则

[返回全项目接口文档](00-全项目接口说明与请求示例.md)。对应功能：后端、MySQL 和 Redis 连通性检查；对应需求 REQ-FOUNDATION。

### BASE-01 · 基础健康检查 · GET /api/health

用途：检查后端、MyBatis 数据库查询和 Redis PING。允许匿名访问，只返回组件状态与检查时间，不返回数据库版本、账号、密码或业务数据。

MySQL 与 Redis 均正常时 HTTP 200，响应示例：

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "status": "UP",
    "components": {"mysql": "UP", "redis": "UP"},
    "checkedAt": "2026-10-17T20:00:00+08:00"
  }
}
```

上面的时间仅为形状示例；实际结果以真实请求为准。任一依赖不可用时 HTTP 503、`code=50300`、`data.status=DOWN`，对应组件为 `DOWN`。检查不会写入数据库或 Redis。


### 请求示例、权限与错误

无参数、无请求体、无需登录：

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/api/health' -Method Get
```

也可将端口改为 5173，通过前端开发代理检查同一路径。失败示例：

```json
{"code":50300,"message":"基础服务暂不可用","data":{"status":"DOWN","components":{"mysql":"UP","redis":"DOWN"},"checkedAt":"2026-10-18T20:00:00+08:00"}}
```

上例只说明响应形状。错误码 `50300` 表示至少一个依赖不可用；公共错误语义见总文档。

### 页面与实现

`BASE-P01 · 工作台连接状态 · /workbench`：显示检查中、连接正常或连接失败，并支持刷新/重试。只显示整体状态，具体组件可通过接口查看。

前端：`frontend/src/api/health.js`、`frontend/src/views/workbench/WorkbenchView.vue`。

后端：`backend/src/main/java/com/bishe/crm/module/health/` 下的 HealthController、InfrastructureHealthService，以及基础设施中的 DatabaseProbeMapper。验证见 [后端记录](../backend-verification.md) 与 [前端记录](../frontend-verification.md)。此接口不代表业务功能已经验收。

## AUTH · 账号认证与密码接口、示例及规则

[返回全项目接口文档](00-全项目接口说明与请求示例.md)。对应功能：账号登录 / JWT / 本人信息 / 首次与普通改密 / 退出；对应需求 REQ-AUTH。

后端入口：AuthController；实现：AuthService、JwtTokenService、JwtAuthenticationFilter、SystemUserMapper。请求基址为后端 http://127.0.0.1:8080，前端开发时通过 /api 代理调用。

### AUTH-01 · 账号登录 · POST /api/auth/login

请求 JSON：

```json
{"username":"你的账号","password":"你的当前密码"}
```

用户名必填、最多 64 个字符；密码必填、最多 72 个字符且不超过 BCrypt 的 72 字节限制。账号不存在、密码错误、账号待启用/停用、非管理员未分配有效团队或团队停用，均返回 HTTP 401、`40101` 和相同提示，不暴露具体账号状态。不开放公众自助注册。

成功为 HTTP 200：

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "accessToken": "<签名后的 JWT>",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "expiresAt": "2026-10-18T08:00:00Z",
    "user": {
      "id": 123,
      "username": "示例账号",
      "realName": "示例姓名",
      "phone": null,
      "email": null,
      "roleCode": "SPECIALIST",
      "teamId": 12,
      "teamName": "示例团队",
      "mustChangePassword": true
    }
  }
}
```

上述用户、时间和令牌仅示意响应形状，实际结果以请求为准。角色为 `ADMIN`、`MANAGER`、`SPECIALIST`；管理员可以不属于团队，此时团队字段为 null。不返回密码、哈希或内部会话版本。成功登录更新 `last_login_at`，同一账号重新登录使前一个令牌失效。

### AUTH-02 · 当前用户 · GET /api/auth/me

请求头：`Authorization: Bearer <accessToken>`。返回 `data` 为上述 `user` 对象。身份来自令牌 subject 与当前数据库账号，不接受客户端指定用户 id；角色、团队、账号状态和首次改密标记均实时查库。首次改密之前也可使用此接口。

### AUTH-03 · 首次/普通改密 · POST /api/auth/password

需要有效 Bearer 令牌，首次改密和后续自行改密共用此接口。请求 JSON：

```json
{
  "oldPassword": "你的当前密码",
  "newPassword": "ExampleNew123!",
  "confirmPassword": "ExampleNew123!"
}
```

新密码采用本轮实现默认规则：8～64 位，至少含一个英文字母和一个数字，允许英文标点，不允许空格、中文或控制字符。两次新密码必须相同，且不能与原密码相同。密码不做 trim 或自动大小写转换。

成功返回 HTTP 200、`{"code":0,"message":"操作成功","data":null}`。同一 MySQL 事务内更新 BCrypt 哈希、清除首次改密标记、推进版本号，并写入一条 `PASSWORD_CHANGED` 操作日志；日志不保存密码、哈希或令牌。任何一步失败均回滚。并发提交通过数据库版本及旧哈希条件更新，只允许一个请求成功，其余返回 401 或 409。

改密成功后所有旧令牌失效，客户端应清除旧令牌并使用新密码重新登录。本接口不自动返回新令牌。

### AUTH-04 · 账号退出 · POST /api/auth/logout

需要有效 Bearer 令牌，无请求体。成功返回 HTTP 200、`code=0`、`data=null`，后端推进账号版本撤销当前会话；前端同时清除本地令牌。重复使用已退出或被替换的令牌返回 HTTP 401、`40102`。首次改密前也可以退出。

### 首次改密与会话约定

`mustChangePassword=true` 时，后端仅允许该账号查询本人信息、修改密码和退出；访问其他受保护路径返回 HTTP 403、`40301`。健康检查和登录仍按公共接口处理。该限制在后端过滤器执行，不能靠手工请求业务接口绕过。

本轮采用单账号单会话、HS256 签名 JWT，有效期默认 7200 秒；校验签名、算法白名单、签发者、到期时间、签发时间及必要身份字段。只接受 Authorization 请求头，不接受 URL 参数或 Cookie 令牌，不创建 HTTP Session。公共健康/登录接口忽略随请求附带的旧令牌，便于登录失效后重新登录。

为保持 18 表结构不变，令牌携带现有 `sys_user.version`，每个受保护请求比对数据库中的版本；登录、退出和改密都会推进版本。其他推进用户行版本的操作也会使已有会话失效。账号管理的停用、权限/团队调整、重置密码已同步推进版本；业务计数更新需明确是否应影响会话，不能无意复用认证版本约定。Redis 不保存本轮会话，认证查库失败时拒绝请求，不退回仅信任旧令牌。

签名密钥来自 `CRM_JWT_SECRET` 或忽略的本地配置，使用至少 32 随机字节的 Base64 字符串。没有可用密钥时应用拒绝启动；修改密钥后原令牌失效。`CRM_JWT_TTL_SECONDS` 可设为 60～86400 秒；本轮未实现刷新令牌、忘记密码和登录失败锁定；登录与改密页面见认证模块文档。

账号管理与内部申请已见 [USER](03-内部账号申请与管理.md)，本人资料编辑及保存后的令牌更新见 [PROFILE](04-个人资料维护.md)。当前用户/团队和客户基础查询已落实本人/团队/全量范围与公海脱敏，见 [PERM](05-角色与数据范围.md)；其余业务动作、商机协作、附件和导出权限随对应模块继续接入。

### AUTH · 可操作请求示例

以下在 PowerShell 中执行，账号/密码由交互输入，不把实际密码写入示例或版本库。前端开发基址可改为 `http://127.0.0.1:5173`。

```powershell
$base = 'http://127.0.0.1:8080'
$credential = Get-Credential -UserName 'admin' -Message '输入 CRM 账号密码'
$loginBody = @{
    username = $credential.UserName
    password = $credential.GetNetworkCredential().Password
} | ConvertTo-Json
# AUTH-01 · 登录
$result = Invoke-RestMethod -Uri "$base/api/auth/login" -Method Post -ContentType 'application/json' -Body $loginBody
$headers = @{ Authorization = "Bearer $($result.data.accessToken)" }
# AUTH-02 · 当前用户
Invoke-RestMethod -Uri "$base/api/auth/me" -Method Get -Headers $headers
```

`AUTH-02` 完整成功响应示例（姓名、id 和团队均为示例）：

```json
{"code":0,"message":"操作成功","data":{"id":123,"username":"示例账号","realName":"示例姓名","roleCode":"SPECIALIST","teamId":12,"teamName":"示例团队","mustChangePassword":true}}
```

首次改密和普通改密均调用 `AUTH-03`。这里通过隐藏输入读取新密码：

```powershell
$newSecure = Read-Host '新密码（8～64 位，字母和数字）' -AsSecureString
$confirmSecure = Read-Host '再次输入新密码' -AsSecureString
$passwordBody = @{
    oldPassword = $credential.GetNetworkCredential().Password
    newPassword = ([System.Net.NetworkCredential]::new('', $newSecure)).Password
    confirmPassword = ([System.Net.NetworkCredential]::new('', $confirmSecure)).Password
} | ConvertTo-Json
Invoke-RestMethod -Uri "$base/api/auth/password" -Method Post -Headers $headers -ContentType 'application/json' -Body $passwordBody
# 成功后旧 headers 已失效，必须重新登录获得新令牌。
Remove-Variable loginBody, passwordBody, credential, headers, result, newSecure, confirmSecure
```

需要退出时，先按登录示例获得当前有效的 `$headers`，再执行 `AUTH-04`：

```powershell
Invoke-RestMethod -Uri "$base/api/auth/logout" -Method Post -Headers $headers
```

`AUTH-03` 与 `AUTH-04` 的成功响应均为：

```json
{"code":0,"message":"操作成功","data":null}
```

常见失败：字段或密码格式不符 `40001`；原密码错误 `40002`；新旧密码相同 `40003`；缺少身份 `40100`；登录失败 `40101`；过期/撤销/无效令牌 `40102`；无权限 `40300`；必须先改密 `40301`；并发冲突 `40900`；依赖故障 `50300`。HTTP 状态见总文档。失败响应例如：

```json
{"code":40002,"message":"原密码不正确","data":null}
```

### AUTH · 页面与接口对应

- `AUTH-P01 · 登录页 · /login`：调用 **AUTH-01**；空值/长度校验、提交中禁用、错误提示；首次登录进入改密，其他登录恢复合法的站内目标页。没有公众自助注册和忘记密码入口。
- `AUTH-P02 · 首次/普通改密页 · /change-password`：身份由 **AUTH-02** 确认，提交 **AUTH-03**；首次改密只能完成改密或通过 **AUTH-04** 退出，普通改密可返回原页面；成功清除旧会话并返回登录。
- `AUTH-P03 · 个人中心 · /account`：调用 **AUTH-02** 展示本人账号、姓名、角色、团队与改密状态；可刷新或进入普通改密。可以编辑姓名、电话和邮箱，调用 PROFILE-01；保存成功后自动替换令牌与当前用户。
- `AUTH-P04 · 工作空间框架 · /workbench 等受保护页`：每次进入保护路由调用 **AUTH-02**；右上角账号菜单调用 **AUTH-04** 退出，确认后由后端撤销令牌，再清除浏览器身份。

前端使用 `localStorage['crm.access-token']` 保存 JWT，密码不持久化。用户身份与角色从当前后端响应获取，不从本地缓存或 JWT 内容自行授权。401 清除当前失效会话；503/网络失败显示可重试反馈并保留令牌；退出失败不会伪装成后端退出成功。跨标签页账号变更会隐藏旧身份界面，后续导航重新确认新身份。登录恢复地址只允许站内路径。

三类角色菜单：专员显示业务、任务和看板入口；经理额外显示审批中心/团队管理；管理员额外显示账号管理。账号、团队、内部申请及客户基础查询已开放，其他业务仍标待开发。菜单与路由只辅助交互，后端权限落实范围见 PERM 文档。

前端实现：`frontend/src/` 下的 `views/auth/`、`views/account/AccountView.vue`、`layouts/AppLayout.vue`、`router/`、`store/auth.js`、`api/auth.js`、`api/http.js`。后端实现：`backend/src/main/java/com/bishe/crm/module/auth/`，JWT 与认证过滤器位于该模块的 `security/`；本轮前端无数据库结构变更。

验证见 [认证后端记录](../auth-verification.md)、[前端联调记录](../frontend-verification.md)；主题与页面规则见 [前端框架设计](../ui/frontend-foundation.md)。

## USER 账号申请与管理

对应任务清单 C7 用户注册与登录、C9 角色差异化数据访问与操作权限；登录接口见 [AUTH](02-账号认证与密码.md)。基址、统一响应、错误码见 [全项目接口文档](00-全项目接口说明与请求示例.md)。以下均需 Bearer JWT，并已完成首次改密。

### 规则与页面

- 内部注册采用经理代本团队新专员申请、管理员审核。申请人不能指定团队、角色或初始密码；没有匿名注册入口。
- 管理员可直接创建 ADMIN、MANAGER、SPECIALIST。ADMIN 不绑定团队；另两类必须绑定启用的团队。现有团队用于选择，本轮不开放团队新增/删除。
- 用户名 3～64 位，以字母/数字开头，后续允许字母、数字、点、横线、下划线；唯一且不可改。姓名必填、最多 80 字；电话可空，6～32 位数字、空格、加号、横线或括号；邮箱可空、有效格式且最多 160 字，非空邮箱唯一。
- 初始/重置密码 8～64 位 ASCII 可见字符，必须含字母与数字，不允许空格。只保存 BCrypt 哈希；接口不回显明文或哈希。管理员在表单中自行指定并告知使用人，下一次登录强制改密。
- 申请使用 `sys_user.PENDING` 保留账号名，随机不可用初始密码；`crm_approval` 保存 ACCOUNT_OPEN 审批。通过后 ACTIVE；驳回仍 PENDING、不能登录。原申请经理可以重新提交被驳回的申请。旧处理意见保留在同事务操作日志中。
- 权限/团队/启停/密码重置推进账号版本，旧会话失效。停用不自动回收、转交或释放客户。存在客户、负责商机、合同或有效协作关系时禁止调整角色/团队，先由后续业务交接流程处理。
- 管理员不能通过管理接口调整本人权限、启停或重置本人密码；本人改密走 AUTH-03。受事务锁保护的最后一个启用管理员不能被降权/停用。
- 团队的 manager_id 是主要对接经理；新经理在该字段空缺时补入，不覆盖已有经理。同一团队的 MANAGER 账号按本团队范围工作；离开该团队或被停用时清理其主要经理指向。
- `/system` 账号管理、`/team` 团队成员复用 UsersView；`/approvals` 为账号申请/审核。经理只看本团队成员和自己当前团队的申请，管理员看全部。

### USER-01 账号分页 GET /api/users

参数：`page=1`、`size=20`（1～100）、可选 `keyword`（账号或姓名，最多 80 字）、`roleCode`、`accountStatus`。

角色：管理员全量，经理本团队，专员仅本人。范围在 SQL 中过滤，分页总数同范围；传入 userId/teamId 等额外参数不能扩大范围。

示例：`GET /api/users?page=1&size=20&keyword=east&accountStatus=ACTIVE`。

成功 data 示例：

```json
{"total":1,"list":[{"id":123,"username":"example.sales","realName":"示例专员","phone":null,"email":null,"roleCode":"SPECIALIST","teamId":12,"teamName":"示例团队","accountStatus":"ACTIVE","mustChangePassword":true,"version":0,"lastLoginAt":null}]}
```

`version` 是管理表单提交的并发版本，登录也会推进，编辑前应重新取详情。示例数据均为形状说明。

### USER-02 账号详情 GET /api/users/{id}

与 USER-01 相同范围；越权 ID 与不存在 ID 均返回 40400。成功 data 为 USER-01 的一条记录。参数 id 为正整数。

### USER-03 所属团队选择 GET /api/teams

管理员可见全部团队，经理/专员仅当前团队。data 为数组：

```json
[{"id":12,"teamCode":"EAST","teamName":"示例团队","managerId":23,"managerName":"示例经理","enabled":true}]
```

该接口只提供团队选择与主要经理资料，不代表已开放团队维护。

### USER-04 管理员直接建号 POST /api/users

仅 ADMIN。请求示例：

```json
{"username":"example.sales","realName":"示例专员","phone":null,"email":null,"roleCode":"SPECIALIST","teamId":12,"initialPassword":"Example123!"}
```

成功 data 为账号 VO；状态 ACTIVE、mustChangePassword=true。建号与 ACCOUNT_CREATED 审计同事务。

### USER-05 角色团队与启停 PUT /api/users/{id}/access

仅 ADMIN。请求示例：

```json
{"version":3,"roleCode":"SPECIALIST","teamId":12,"accountStatus":"DISABLED"}
```

accountStatus 只允许 ACTIVE、DISABLED，PENDING 账号只能通过申请审核开通。成功 data=null；记录 ACCOUNT_ACCESS_CHANGED，旧令牌失效。版本过期返回 40900，待交接返回 40901，自身调整或不合法团队/角色配置返回 40004。

### USER-06 管理员重置密码 POST /api/users/{id}/reset-password

仅 ADMIN，目标不能为本人或 PENDING。请求：

```json
{"version":3,"initialPassword":"ResetExample123!"}
```

新密码不能与当前密码相同。成功 data=null，PASSWORD_RESET 审计与哈希更新同事务，旧令牌失效、下次登录强制改密。对 DISABLED 账号重置不会启用它。

### USER-07 申请列表 GET /api/account-applications

ADMIN/MANAGER；`page`、`size` 同公共分页。管理员全量；经理仅自己提交且目标仍在当前团队的申请。

data 示例：

```json
{"total":1,"list":[{"id":456,"bizId":123,"username":"example.new","realName":"新专员","teamId":12,"teamName":"示例团队","applicantName":"示例经理","approvalStatus":"PENDING","reason":"新成员入职","reviewOpinion":null,"version":0,"submittedAt":"2026-10-18T21:00:00","processedAt":null}]}
```

### USER-08 经理代申请 POST /api/account-applications

仅 MANAGER，请求：

```json
{"username":"example.new","realName":"新专员","phone":null,"email":null,"reason":"新成员入职"}
```

reason 必填、最多 1000 字；角色固定 SPECIALIST、团队由当前登录人决定。成功 data 为审批 id，例如 456。记录 ACCOUNT_APPLIED。用户名/非空邮箱重复返回 40900；不创建可登录的待审账号。

### USER-09 管理员审核 POST /api/account-applications/{id}/review

仅 ADMIN，请求：

```json
{"version":0,"approved":true,"opinion":"资料核对通过","initialPassword":"Example123!"}
```

驳回：`{"version":0,"approved":false,"opinion":"请先核对成员资料","initialPassword":null}`。

opinion 必填、最多 500 字，通过必须提供符合规则的初始密码。只处理 PENDING；重复/并发提交只成功一次，其他返回 40900。账号开通、审批结果与 ACCOUNT_APPROVED/ACCOUNT_REJECTED 审计同事务，审计不保存密码。

### USER-10 驳回后重提 POST /api/account-applications/{id}/resubmit?version=1

仅原申请 MANAGER，且仍属于目标团队。无请求体，version 非负。只允许 REJECTED → PENDING；审批版本推进，旧意见转为操作日志历史。成功 data=null，记录 ACCOUNT_RESUBMITTED。不能重提他人的申请或已通过的申请。

### 可执行请求与实现位置

先按 AUTH 文档登录获得 `$headers` 后，在 PowerShell 执行：

```powershell
$base = 'http://127.0.0.1:8080'
Invoke-RestMethod "$base/api/users?page=1&size=20" -Headers $headers
Invoke-RestMethod "$base/api/teams" -Headers $headers
$body = @{ username='example.new'; realName='新专员'; reason='团队新增成员' } | ConvertTo-Json
Invoke-RestMethod "$base/api/account-applications" -Method Post -Headers $headers -ContentType 'application/json' -Body $body
```

示例 id/用户名/密码需替换；示例不会自动创建到数据库。所有无结果操作成功响应为 `{"code":0,"message":"操作成功","data":null}`。错误沿用公共响应，新增 40004 账号规则、40901 待业务交接。未完成首次改密返回 40301；操作权限不足 40300。

后端：`module/system/controller/AccountController.java`、`service/AccountService.java`、`mapper/AccountMapper.java`、dto/vo。前端：`api/users.js`、`views/account/UsersView.vue`、`ApplicationsView.vue`。业务时区 Asia/Shanghai；本轮无表结构迁移。验证见 [用户权限验证](../user-permissions-verification.md)。

## PROFILE 个人资料维护

对应任务清单 C8；[返回总文档](00-全项目接口说明与请求示例.md)。当前信息通过 AUTH-02 `GET /api/auth/me` 读取，新增 phone、email；登录响应中的 user 同样包含这两项。

### PROFILE-01 修改本人资料 PUT /api/account/profile

所有已完成首次改密的登录角色可用；身份只取当前 JWT 对应账号，不接受客户端指定目标用户。请求 DTO 白名单仅姓名、电话、邮箱，额外的 id、roleCode、teamId 不会写入。

请求示例：

```json
{"realName":"张三","phone":"13812345678","email":"zhangsan@example.test"}
```

姓名必填、最多 80 字，保存时去掉首尾空格。电话可空，非空 6～32 位数字/空格/加号/括号/横线；邮箱可空、有效格式、最多 160 字且非空时唯一。空值传 null 表示清空。

成功 data 采用 AUTH-01 的 LoginVO 结构：`{accessToken,tokenType,expiresIn,expiresAt,user}`，user 是更新后的本人资料。更新版本、PROFILE_UPDATED 审计同事务；返回新 JWT，旧 JWT 失效。前端必须替换 token 和 Pinia user，再继续访问。审计只记录修改动作，不保存联系方式明文、密码或令牌。

响应形状示例：

```json
{"code":0,"message":"操作成功","data":{"accessToken":"<新的JWT>","tokenType":"Bearer","expiresIn":7200,"expiresAt":"2026-10-18T15:00:00Z","user":{"id":123,"username":"example.sales","realName":"张三","roleCode":"SPECIALIST","teamId":12,"teamName":"示例团队","mustChangePassword":false,"phone":"13812345678","email":"zhangsan@example.test"}}}
```

错误：字段不符 40001，未登录/旧令牌 40100/40102，未首次改密 40301，重复邮箱或并发变更 40900，依赖故障 50300。不得用重新登录掩盖保存失败；网络失败时保留表单，成功后才替换本地身份。其他标签页检测到 token 变化后重新确认身份。

### 页面与可执行示例

`/account`：编辑资料 → 输入姓名/电话/邮箱 → 保存或取消；支持刷新、查看账号/角色/团队、进入改密。取消不发送保存请求。保存后页面和顶栏姓名同步更新，刷新页面仍保留数据库结果。

获得有效 `$headers` 后：

```powershell
$body = @{ realName='张三'; phone=$null; email=$null } | ConvertTo-Json
$result = Invoke-RestMethod 'http://127.0.0.1:8080/api/account/profile' -Method Put -Headers $headers -ContentType 'application/json' -Body $body
$headers = @{ Authorization = "Bearer $($result.data.accessToken)" }
Invoke-RestMethod 'http://127.0.0.1:8080/api/auth/me' -Headers $headers
```

后端 AccountService.profile；前端 `AccountView.vue`、`store/auth.js:updateProfile`、`api/auth.js:saveProfile`。不提供头像上传、修改登录账号或自选角色/团队。验证见 [用户权限验证](../user-permissions-verification.md)。

## PERM 角色与数据范围

对应任务清单 C9；[返回总文档](00-全项目接口说明与请求示例.md)。权限包含后端动作授权、SQL 数据范围和响应字段白名单；菜单与路由用于辅助交互。

### 已实现的权限

- ADMIN：全部账号/团队/内部账号申请；建号、角色团队调整、启停、密码重置及账号申请审核。私人客户查询为全系统。
- MANAGER：本团队成员、本人当前团队的账号申请；可代新专员申请、重新提交自己被驳回的申请。私人客户查询为本团队。
- SPECIALIST：本人账号资料，不能访问账号审批或管理动作。私人客户查询为本人归属。
- 公海客户基础查询向登录角色开放，电话在 SQL 中脱敏；短号统一返回 `****`，空值仍为 null。信用代码、决策链、合同金额、附件路径等不在当前 VO 中返回。
- 原负责人：当前 ownership_seq 对应的有效交接日志，且 handover_readonly_until 尚未到期，才额外获得客户基础查询；标记 readonly=true。过期或旧归属轮次不能继续访问。
- 商机协作不授予客户全档案访问；本轮客户查询没有以协作关系绕过范围。商机专属协作入口将在商机模块接入。
- 未授权详情统一 40400，既不泄露对象是否存在，也不能通过猜 ID 访问。分页 SQL 和总数均包含相同范围。

账号、团队、申请入口和动作权限见 [USER](03-内部账号申请与管理.md)。权限变化通过账号版本撤销旧令牌；后续登录和受保护请求均实时读取数据库身份。

### PERM-01 客户范围分页 GET /api/customers

参数 `page=1`、`size=20`、`sea=PRIVATE|PUBLIC`（默认 PRIVATE）。身份、owner/team 条件由后端生成，客户端传 ownerId/teamId 不会扩大权限。

成功 data 示例：

```json
{"total":1,"list":[{"id":321,"customerName":"示例客户","primaryPhone":"138****5678","sourceCode":null,"industryCode":null,"customerStatus":"NEW","seaType":"PUBLIC","ownerId":null,"ownerName":null,"teamName":null,"readonly":true}]}
```

PRIVATE 范围内的电话完整显示；PUBLIC 无论管理员或其他角色都脱敏。数据来自真实数据库，空库返回 total=0、list=[]。

### PERM-02 客户基础详情 GET /api/customers/{id}

正整数 id，成功 data 为 PERM-01 单条对象。同样应用 owner/team、公海、交接有效期与字段白名单；不能绕过列表权限。该接口只返回基础档案摘要，不包含联系人全档案、跟进或商业资料。

错误：无登录 40100，失效身份 40102，需先改密 40301，范围外/不存在 40400，参数错误 40000/40001，依赖故障 50300。

### 页面和请求示例

`/customers` 查询 PRIVATE、`/public-pool` 查询 PUBLIC；支持分页、刷新、查看基础详情、加载/空/错误状态。页面明确说明本轮只开放查询，新增、编辑、跟进、领取等动作未开放。

```powershell
Invoke-RestMethod 'http://127.0.0.1:8080/api/customers?sea=PRIVATE&page=1&size=20' -Headers $headers
Invoke-RestMethod 'http://127.0.0.1:8080/api/customers?sea=PUBLIC&page=1&size=20' -Headers $headers
Invoke-RestMethod 'http://127.0.0.1:8080/api/customers/321' -Headers $headers
```

实现：`module/auth/security/DataScope.java`、`module/system/mapper/AccountMapper.java`、`module/customer/`；动作授权用 Spring Security `@PreAuthorize`，关系过滤用参数化 MyBatis SQL。沿用 18 表简化方案，不增加角色权限关联表、全 SQL 拦截器或自建 ThreadLocal。
