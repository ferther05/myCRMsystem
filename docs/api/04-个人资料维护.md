# PROFILE 个人资料维护

对应任务清单 C8；[返回总文档](00-全项目接口说明与请求示例.md)。当前信息通过 AUTH-02 `GET /api/auth/me` 读取，新增 phone、email；登录响应中的 user 同样包含这两项。

## PROFILE-01 修改本人资料 PUT /api/account/profile

所有已完成首次改密的登录角色可用；身份只取当前 JWT 对应账号，不接受客户端指定目标用户。请求 DTO 白名单仅姓名、电话、邮箱，额外的 id、roleCode、teamId 不会写入。

请求示例：

```json
{"realName":"张三","phone":"13812345678","email":"zhangsan@example.test"}
```

姓名必填、最多 80 字，保存时去掉首尾空格。电话可空，非空 6～32 位数字/空格/加号/括号/横线；邮箱可空、有效格式、最多 160 字且非空时唯一。空值传 null 表示清空。

成功 data 采用 AUTH-01 的 LoginVO 结构：`{accessToken,tokenType,expiresIn,expiresAt,user}`，user 是更新后的本人资料。更新版本、PROFILE_UPDATED 审计同事务；返回新 JWT，旧 JWT 失效。前端必须替换 token 和 Pinia user，再继续访问。审计只记录修改动作，不保存联系方式明文、密码或令牌。

响应形状示例：

```json
{"code":0,"message":"操作成功","data":{"accessToken":"<新的JWT>","tokenType":"Bearer","expiresIn":7200,"expiresAt":"2026-10-18T15:00:00Z","user":{"id":123,"username":"example.sales","realName":"张三","roleCode":"SPECIALIST","teamId":12,"teamName":"示例团队","mustChangePassword":false,"phone":"13812345678","email":"zhangsan@example.test"}}}
```

错误：字段不符 40001，未登录/旧令牌 40100/40102，未首次改密 40301，重复邮箱或并发变更 40900，依赖故障 50300。不得用重新登录掩盖保存失败；网络失败时保留表单，成功后才替换本地身份。其他标签页检测到 token 变化后重新确认身份。

## 页面与可执行示例

`/account`：编辑资料 → 输入姓名/电话/邮箱 → 保存或取消；支持刷新、查看账号/角色/团队、进入改密。取消不发送保存请求。保存后页面和顶栏姓名同步更新，刷新页面仍保留数据库结果。

获得有效 `$headers` 后：

```powershell
$body = @{ realName='张三'; phone=$null; email=$null } | ConvertTo-Json
$result = Invoke-RestMethod 'http://127.0.0.1:8080/api/account/profile' -Method Put -Headers $headers -ContentType 'application/json' -Body $body
$headers = @{ Authorization = "Bearer $($result.data.accessToken)" }
Invoke-RestMethod 'http://127.0.0.1:8080/api/auth/me' -Headers $headers
```

后端 AccountService.profile；前端 `AccountView.vue`、`store/auth.js:updateProfile`、`api/auth.js:saveProfile`。不提供头像上传、修改登录账号或自选角色/团队。验证见 [用户权限验证](../user-permissions-verification.md)。
