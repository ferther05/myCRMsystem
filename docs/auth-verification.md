日期：2026-10-18，业务时区 Asia/Shanghai。对应 REQ-AUTH；参考详细设计 3.2.3、过程指南 4.2、已确认 BD-08/BD-12，关键审计遵循 BD-06。范围为后端认证功能，不代表整个认证权限阶段通过。

## 实现与使用

代码位于 `backend/src/main/java/com/bishe/crm/module/auth/`，用户访问位于 `module/system/mapper/SystemUserMapper.java`；接口契约见 [后端接口约定](backend-api.md)。

- POST `/api/auth/login`：账号密码校验、返回 Bearer JWT 与本人信息；记录登录时间，替换旧会话。
- GET `/api/auth/me`：按令牌身份查询当前用户，实时核对状态、角色、团队和版本。
- POST `/api/auth/password`：校验原密码、新密码与确认输入；更新 BCrypt、清除首次改密标记、写安全审计，随后要求重新登录。
- POST `/api/auth/logout`：后端撤销会话，旧令牌不再可用。

首次改密前仅允许本人信息、改密、退出，其他受保护请求返回 40301；这是后端强制限制。默认有效期 2 小时、单账号单会话、8～64 位新密码规则属于本轮简洁实现选择，已写入接口契约，没有将其冒充为原始文档已确认参数。

继续使用 MySQL 8.0.41 的 `crm_system`、最小权限应用账号及原有 18 张表；无 DDL/初始化重跑。会话版本复用 `sys_user.version`，登录、退出、改密或其他推进用户行版本的操作都会使旧会话失效；后续频繁业务计数更新需遵守该约定。JWT 不使用 Redis 存储会话，Redis 仍为原 6380 实例。

JJWT 0.13.0 已核对 Maven Central 正式版本元数据并锁定，沿用 Java 17 / Spring Boot 3.5.16 / MyBatis-Plus 3.5.17。密钥为本机随机生成的 32 字节 Base64 字符串，仅写入 Git 忽略的本地配置，不包含在源码、报告或打包产物中。
