## 产品范围

服务 10～50 人销售团队，采用轻量管理系统。主要角色是销售专员、销售经理和系统管理员。团队隔离按实际成员关系实现；不从参考中的“单团队”推断可省略团队校验。

六个必选模块：用户与权限、客户与联系人、商机、合同与回款、销售数据分析看板、任务与日志。开题报告以“五大模块”概括业务领域，选题审核表和任务清单将“任务与日志”单列为第六模块；最终验收必须覆盖全部六项。组织团队、跟进、公海流转、配置字典和定时扫描贯穿这些模块。

主线为线索/客户录入 → 归属与有效跟进 → 商机推进 → 签约确认 → 回款核销 → 客户终态与流转。商机主阶段为线索 → 跟进 → 报价 → 成交 → 赢单，各阶段需要前置条件、后置动作、操作人和时间，不能将“成交”和“赢单”合并处理。

开题报告明确的研究重点是 B/S 架构下 RBAC 权限模型和有限状态机在销售流程中的工程实践。体现为角色/团队/本人数据范围与字段脱敏、商机合法推进回退、按商机阶段与活跃度双维度回收，以及任务提醒闭环。论文中的设计说明、实现和验证应对应这些机制；“提升转化率”等是目标，未经实验不能写成实测成果。

不扩展为微服务、复杂工作流引擎或财务账务系统。合同条款谈判在线下；系统登记过程、资料、确认和回款，不处理凭证记账与税务。

## 技术基线

Java 17；Spring Boot 3；MyBatis-Plus 3.5 系列；Spring Security 6 与 JWT；MySQL 8；Redis 7。前端使用 Vue 3、Vite、Element Plus、Pinia、Vue Router、axios 和 ECharts。部署目标是 Java jar 与 Nginx 静态站点/反向代理。

文档列出的 Spring Boot 3.0.x、Vite 5.x、Node.js 18+ 等是原始选型，不等于必须使用失去维护的版本。环境和依赖定稿时核对支持周期与组合兼容性，在保持用户技术方向的前提下记录实际版本。TypeScript、Flyway、MinIO、Docker、WebSocket 等未全部确认，不作为既成要求。

## 关键约束

- 客户同一时刻只有一个归属人；协作关系发生在商机层，不授予客户全档案访问。
- 有效跟进包含方式、具体联系人、实质结果及后续动作时间；无效记录不刷新有效时间。
- 公海回收同时考虑商机阶段与活跃度，并有停滞阈值和二次复核；领取需要乐观锁等数据库并发保护及限额限频，不能仅按客户未更新天数回收。
- 公海领取、归属转交、资料版本与回款登记需要数据库级并发保护和可追溯记录。
- 字段分级 L1～L5 在响应、日志和导出中一致处理；下载权限独立验证。
- 资料旧版本保留；回款金额不能超合同余额；重复业务提交不能重复生效。
- 任务与日志属于必选交付：自动产生逾期回款、长期未跟进、商机停滞等待办；同一事件每日仅提醒一次，问题处理后自动解除，关键数据变更可追溯。
- 任务清单另外明确用户个人信息维护、签订进度追踪；看板包含排行、漏斗、转化率、回款统计与趋势。“用户注册”与原设计管理员建号的差异见 BD-12。
- 状态联动与回收机制存在待统一表述，见 [业务决策记录](business-decisions.md)，不能将本概述代替决策。
